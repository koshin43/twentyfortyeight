# 2048 — Design Spec

Date: 2026-10-01
Status: Draft

## 1. Purpose

A personal 2048: the classic sliding-tile game with no ads, popups or tracking, plus what other versions lack — stats, playing on past the win, three board sizes — and a twist style, **Wild**, that adds Jokers, stones and strategic power-ups.

The owner plays equally on a phone (iPhone and Android) and a laptop. Each device keeps its own games and stats.

Success looks like:

- The app opens instantly, including offline, straight onto the board.
- Swipes feel immediate, with tiles sliding smoothly like the original.
- Wild feels strategic without being easy. Every number that tunes it lives in this spec.

## 2. Decisions already made

| Topic | Decision |
|---|---|
| App type | Installable web app (PWA) named "2048". Phone and laptop are equally important. |
| Data location | On the device only. No accounts, no server, no sync. Each device has its own game and stats. |
| Board sizes | 3×3, 4×4, 5×5. One game at a time; changing size starts a new game. |
| Styles | **Classic** (plain 2048) and **Wild** (Jokers, stones, power-ups). |
| Pace | **Endless** or **Blitz** (3-minute timed game). Every size × style × pace combination is allowed: 12 stat sets. |
| Win tile | 512 on 3×3, 2048 on 4×4, 8192 on 5×5. Play always continues past it. |
| Undo | Only as a Wild power-up. Classic has no undo. |
| Scoring | Classic: each merge adds the new tile's value. No multipliers. |
| Stats | Per set: best score, best tile, games played, wins and win rate, top 10. No reset. |
| Look | The original 2048 palette, light only. |
| Feedback | Generated sound effects and vibration (where the device allows it), one on/off toggle. |
| Hosting | GitHub Pages, deployed by a workflow on push to `master`. |

Per-size values used throughout:

| Board | Win tile | Power recharge | Row's worth (N) |
|---|---|---|---|
| 3×3 | 512 | 50 moves | 3 |
| 4×4 | 2048 | 150 moves | 4 |
| 5×5 | 8192 | 300 moves | 5 |

## 3. Rules

### 3.1 Core rules (Classic, and the base of Wild)

- A new game places two tiles in random empty cells. Each is a 2 (90%) or a 4 (10%).
- A swipe (up, down, left, right) slides every tile as far as it can go in that direction. Two equal number tiles that meet merge into one tile of double the value.
- Each tile merges at most once per swipe. Merges resolve starting from the edge the swipe moves towards. Swiping left: `2 2 2 _` → `4 2 _ _`; `2 2 2 2` → `4 4 _ _`; `4 4 8 _` → `8 8 _ _`.
- A swipe that changes nothing is ignored: no tile appears and it does not count as a move.
- A **move** is a swipe that changes the board. After every move one new tile appears in a random empty cell: a 2 (90%) or a 4 (10%), except where Wild replaces it (3.2).
- Each merge adds the resulting tile's value to the score.
- **Best tile** is the highest number tile the game has ever had. It never goes down, even if that tile is later smashed or undone.
- A game is **won** once its best tile reaches the win tile. A won game stays won.
- Classic **game over**: no swipe would change the board.

### 3.2 Wild: room and special spawns

**Room** measures how much space the board leaves to play: **room = empty cells + possible merges**.

- A possible merge is a pair of tiles next to each other in a row or column, with only empty cells between them and no stone between them, that would merge on a swipe: two equal numbers, or a Joker and a number. Each such pair counts once. Example row: `2 2 2 _` has two possible merges.
- Room is measured after a move's slides and merges and after any stone crumbles, just before the new tile appears.

With N the row's worth for the board size (2. table), the new tile is a special tile with this chance:

| Room R | Special tile | Chance |
|---|---|---|
| R ≤ N | Joker | 15% |
| N < R < 2N | Joker | 15% × (2N − R) / N |
| R = 2N | none | 0% |
| 2N < R < 4N | Stone | 15% × (R − 2N) / (2N) |
| R ≥ 4N | Stone | 15% |

- At most one Joker and one stone can be on the board at a time.
- Stones can appear only once the game's best tile is 128 or more.
- When the roll picks a special tile that isn't allowed, or picks no special tile, the new tile is a normal 2 (90%) or 4 (10%).
- The two starting tiles are always normal.

### 3.3 Wild: Joker and stone

**Joker (★)**

- Slides like any tile.
- Merges with any number tile; the result is double that number (Joker + 64 → 128) and scores like a normal merge.
- Never merges with another Joker or with a stone.
- Follows the merge-once and leading-edge rules. Swiping left: `★ 2 2 _` → `4 2 _ _`.

**Stone**

- Never moves and never merges. Tiles slide up against it; it splits its row and column.
- Shows a countdown that starts at 10 and drops by 1 at the end of every move after it appears. When it reaches 0 the stone crumbles, freeing its cell before that move's new tile appears.

**Order of a Wild move:** slide and merge → stone countdown and crumble → power recharge ticks → best tile, win and refill updates → new tile.

### 3.4 Wild: powers

There are three powers: **Smash**, **Swap** and **Undo**.

**Draft.** The New Game panel requires picking exactly 2 powers for a Wild game. Drafted powers start the game ready. The third is **not drafted**.

**States.** Each power is in one state:

| State | Meaning | Shown as |
|---|---|---|
| Ready | Drafted and usable | Solid button |
| Recharging | Drafted, used, recharging | Faded button with a moves-left badge |
| Not drafted | Not part of this game | Dashed outline |
| Bonus | Not drafted, made ready by a refill; one use | Solid button with a small refill mark |

**Using a power** is not a move: no new tile appears, and stone countdowns and recharges do not advance.

- **Smash:** tap Smash, then tap any tile, Joker or stone; it is removed. The last remaining non-stone tile cannot be smashed.
- **Swap:** tap Swap, then tap two tiles; they exchange cells. Stones cannot be selected. Tapping the first selected tile again deselects it. Swap is usable only with at least two non-stone tiles on the board.
- **Undo:** rewinds the last move. It restores the tiles (including stone countdowns), score and random-generator state as they were before that move, so repeating the same swipe produces the same new tile. It does not take back best tile, a win, refills already earned, or Blitz time. Only the most recent move can be undone, and only if no power has been used since it.
- **Targeting:** while Smash or Swap waits for a tile tap, its button is highlighted. Tapping the button again or pressing Esc cancels without spending it. A swipe during targeting cancels targeting and plays the swipe.

**After use:** a drafted power becomes recharging for the board's recharge count (2. table) and drops by 1 every move, becoming ready at 0. A bonus power returns to not drafted.

**Refills.** A refill is earned each time the best tile first reaches a milestone: the win tile, then each doubling of it (4×4: 2048, 4096, 8192, …).

- While a refill is waiting, every power that is recharging or not drafted glows, and the power bar says "Refill: tap a glowing power". Tapping one makes it ready immediately: a recharging power becomes ready; a not-drafted power becomes bonus.
- Only one refill can wait at a time. A refill earned while one is already waiting, or while no power is recharging or not drafted, is wasted.
- Ready powers can still be used normally while a refill waits.

### 3.5 Game end

- **Classic:** game over when no swipe would change the board.
- **Wild:** game over when no swipe would change the board and no power can be used: no ready or bonus Smash, no ready or bonus Swap with two non-stone tiles, no ready or bonus Undo with a move to undo, and no waiting refill.
- **Blitz** (either style) also ends when its clock reaches 0:00 ("Time's Up").

## 4. Game flow

### 4.1 Opening the app

- The app opens straight onto the board and resumes the saved game exactly as it was left.
- With no saved game (first launch), it starts a game with the default setup: 4×4, Classic, Endless, with Smash and Swap as the remembered draft.
- If saved data fails validation, see 9.2.

### 4.2 Starting a new game

- **New Game** opens the New Game panel (6.2), filled in with the last-used setup.
- **Start** ends the current game and begins a new one with the chosen setup, which becomes the last-used setup.
- Closing the panel (✕, tapping outside it, or Esc) keeps the current game.
- Changing board size, style or pace happens only through this panel.

### 4.3 Blitz clock

- The clock counts down from 3:00 and is shown in the TIME box.
- It starts on the first swipe of the game.
- It pauses whenever the app is hidden (switching apps, locking the phone) and whenever the New Game panel or the Stats screen is open. While paused after starting, the TIME box label reads "PAUSED".
- A paused clock resumes on the next swipe or power use.
- The clock keeps running during the win banner and while choosing a refill.
- The saved game always holds the time left; a reopened Blitz game is paused until the next swipe or power use.

### 4.4 Win

- **Endless:** the first time the game is won, a win overlay covers the board: "You made 2048!" (the board's win tile), with **Keep Going** and **New Game**. Keep Going closes it for the rest of the game; New Game opens the New Game panel.
- **Blitz:** a banner "You made 2048!" shows over the top of the board for about 2 seconds; play is never paused.
- When one move both wins and ends the game, only the end overlay shows.

### 4.5 Game end

- An end overlay covers the board: "Game Over" or "Time's Up", the final score, the best tile, "New best!" when the score beats the set's previous best score (or the set has no games yet), and **New Game**, which opens the New Game panel.
- A finished game stays on screen with its end overlay, including after reopening the app, until a new game starts.

### 4.6 Recording games

- A game is recorded in its stat set (size × style × pace) when it ends (game over or time's up), or when it is abandoned by starting a new game while it is unfinished and its score is above 0.
- A game is recorded exactly once. Starting a new game after a finished game records nothing more.
- A record holds the final score, the best tile and the date it ended. Whether it was won follows from its best tile and the set's board size.
- The game screen's BEST box shows the larger of the set's best recorded score and the current score.

## 6. Screens

There is one screen, the game screen, with two dialogs over it: the New Game panel and the Stats screen. On a laptop the same single column is centred.

### 6.1 Game screen

Top to bottom:

1. "2048" title, then SCORE and BEST boxes.
2. The setup label ("4×4 · Wild · Blitz"), and in Blitz the TIME box.
3. **New Game** button, Stats button (📊), sound toggle (🔊 / 🔇).
4. The board: square, as large as the screen allows. Win and end overlays cover the board only; the Blitz win banner sits over its top edge.
5. Wild only: the power bar below the board, with Smash (🔨), Swap (⇄) and Undo (↶) buttons in the states of 3.4.

A notice banner (9.2) appears at the top when saved data was replaced; it closes with ✕.

### 6.2 New Game panel

A panel rising from the bottom of the screen:

- Title "New Game", close ✕.
- **Board:** 3×3 | 4×4 | 5×5. **Style:** Classic | Wild. **Pace:** Endless | Blitz. Each is a segmented control.
- Wild only: **Pick 2 powers**, three toggles (Smash, Swap, Undo).
- When the current game is unfinished, a warning line: "Your current game ends here." If it has points, it continues: "Its 1,284 points will be recorded." A finished game shows no warning.
- **Start**, enabled only when a Wild setup has exactly 2 powers picked.

The panel always shows the last-used draft, even while Classic is selected.

### 6.3 Stats screen

A full-screen dialog over the game, opened by the Stats button, closed by ✕ or Esc.

- Title "Stats", close ✕.
- **Endless | Blitz** segmented control.
- A grid with columns 3×3, 4×4, 5×5 and rows Classic, Wild. Each cell shows that set's best score and best tile, or "—" with no games. Tapping a cell selects it.
- Below the grid, for the selected set: its name ("4×4 · Wild · Endless"), games played, wins with win rate ("9 · 24%"), and **Top 10**: rank, score, ✓ if won, best tile (as a small tile-colored chip), date. With no games: "No games yet".
- The screen opens with the current game's set selected.

## 7. Input, motion and feedback

### 7.1 Input

- **Laptop:** arrow keys or W/A/S/D swipe. Mouse clicks press buttons and pick power targets. Esc cancels targeting, or closes the open dialog.
- **Phone:** a swipe on the board moves in the direction of its larger axis, after a short minimum distance. Taps press buttons and pick power targets. The page never scrolls, zooms or pull-to-refreshes while playing.
- A swipe made while tiles are still animating is accepted immediately; the running animation jumps to its end.
- Swipes are ignored while an overlay or dialog covers the board.

### 7.2 Motion

- Tiles slide to their new cells in about 100ms. Merged tiles pop (a brief scale up and back). New tiles grow in. Stones drop in and crumble away.
- With reduced motion requested by the device, tiles jump to their new cells and nothing pops, grows or drops.

### 7.3 Sound and vibration

Sounds are generated in the browser:

| Event | Sound | Vibration |
|---|---|---|
| Move | Soft tick | — |
| Merge | Pop, higher pitch for higher tile values | — |
| New best tile in this game (from 128) | Bright chime | Short |
| Joker merge | Sparkle | Short |
| Stone lands / crumbles | Thud / crumble | Short (lands only) |
| Power used | Whoosh | — |
| Refill earned | Rising chime | — |
| Win | Fanfare | Long |
| Game Over / Time's Up | Falling tone | Long |

- One toggle (🔊 / 🔇) turns sound and vibration on and off together. It starts on and is remembered on the device.
- Vibration happens only where the device supports it (not on iPhone). On iPhone, sound starts after the first touch, as the browser requires.

## 8. Data model

Stored as one JSON value under the `localStorage` key `2048`.

```ts
type BoardSize = 3 | 4 | 5;
type Style = 'classic' | 'wild';
type Pace = 'endless' | 'blitz';
type Power = 'smash' | 'swap' | 'undo';

interface Save {
  setup: Setup;      // last-used New Game choices
  sound: boolean;    // sound and vibration on
  game: Game;        // the current game; always present after first launch
  stats: Stats;
}

interface Setup {
  size: BoardSize;
  style: Style;
  pace: Pace;
  draft: [Power, Power];   // two different powers; kept even while Classic is chosen
}

type Tile =
  | { id: number; row: number; col: number; kind: 'number'; value: number }
  | { id: number; row: number; col: number; kind: 'joker' }
  | { id: number; row: number; col: number; kind: 'stone'; countdown: number };

interface Position {       // what Undo restores
  tiles: Tile[];
  nextTileId: number;
  score: number;
  random: number;          // seeded generator state, unsigned 32-bit
}

interface Game extends Position {
  size: BoardSize;
  style: Style;
  pace: Pace;
  bestTile: number;
  winSeen: boolean;        // Endless win overlay answered with Keep Going
  wild: Wild | null;       // present exactly when style is 'wild'
  blitzMsLeft: number | null; // present exactly when pace is 'blitz'; 0..180000
}

type PowerState =
  | { status: 'ready' }
  | { status: 'recharging'; movesLeft: number }
  | { status: 'notDrafted' }
  | { status: 'bonus' };

interface Wild {
  powers: Record<Power, PowerState>;
  refillWaiting: boolean;
  undo: Position | null;   // the position before the last move; cleared when a power is used
}

type SetKey = `${BoardSize}-${Style}-${Pace}`;  // e.g. '4-wild-blitz'

interface GameRecord {
  score: number;
  bestTile: number;
  endedAt: number;         // epoch milliseconds
}

interface SetStats {
  played: number;
  wins: number;
  bestTile: number;        // 0 when played is 0
  top: GameRecord[];       // at most 10; highest score first, ties earliest first
}

type Stats = Record<SetKey, SetStats>;  // all 12 keys always present
```

Rules:

- Every field is always present. Optional values are `null`, never omitted.
- Derived, never stored: whether a game or record is won (best tile ≥ the board's win tile), refills already earned (milestones at or below best tile), whether a game has ended (3.5), and a set's best score (`top[0].score`).
- Tiles lie within the board, never share a cell, and have unique ids below `nextTileId`. Number values are powers of two, at least 2. Jokers and stones appear only in Wild games, at most one of each. Stone countdowns are 1–10.
- Score and best tile are non-negative integers. Best tile is a power of two at least as large as every number tile on the board.
- In `wild.powers` exactly one power is `notDrafted` or `bonus`. `movesLeft` is between 1 and the board's recharge count.
- `winSeen` is `false` in Blitz games and in games not yet won.
- In stats, `wins` ≤ `played`, `top.length` ≤ min(`played`, 10), `wins` is at least the number of won records in `top`, and `bestTile` is at least every record's best tile.
- A new game's random seed comes from `crypto.getRandomValues`. The rules draw every random number from the game's own generator state.

## 9. Storage and offline

### 9.1 Saving

- The whole `Save` is written in one `localStorage` write, so a game and its stats can never disagree.
- It is written after every change: each move, power use, refill choice, Keep Going, new game and sound toggle. It is also written when the app is hidden, which keeps Blitz time left.

### 9.2 Reading and validation

- On launch the save is parsed and each part (`setup`, `sound`, `game`, `stats`) is strictly validated on its own against section 8. Unknown fields, missing fields and broken rules are failures.
- A failing part is replaced, never repaired: `game` by a new game with the (valid or default) setup; `stats` by empty stats; `setup` by the default setup; `sound` by on. Unparseable JSON replaces everything.
- When anything was replaced, a notice banner says "Some saved data couldn't be read and was reset:" followed by what (for example "your game, your stats").
- There is no version field and no migration. Any future change to the saved shape makes older saves fail validation and be replaced. This is accepted.

### 9.3 Offline and updates

- A service worker caches the app, so it opens and plays fully offline after the first visit.
- New versions install automatically when online. If an update reloads the page mid-game, the game resumes exactly where it was, with Blitz paused.
- Known risk, accepted: clearing the browser's site data, or losing the device, loses the game and stats.

## 10. Tech stack

- React + TypeScript, built with Vite. CSS Modules beside components; theme values as CSS custom properties defined once.
- No UI component library. Dialogs (New Game panel, Stats screen) are native `<dialog>` elements. Segmented controls are styled radio inputs; the power draft uses styled checkboxes.
- No router: the Stats screen is a dialog over the game.
- `vite-plugin-pwa` for the manifest, icons and service worker.
- Browser platform for everything else: Pointer Events and keyboard events for input, CSS transitions for motion, Web Audio for sounds, the Vibration API, `crypto.getRandomValues` for seeds, `localStorage` for the save.
- A small seeded 32-bit generator (mulberry32) written in the game rules.
- Hosting: GitHub Pages via a workflow on push to `master` that installs, tests, lints, builds and deploys.

## 11. Testing

There are two integration suites and no other tests (AGENTS.md, Testing). Each item below is an edge case that a plausible implementation gets wrong. If the code breaks one of them, at least one test must fail.

### 11.1 Rules scenarios (`game/`)

Each scenario starts from a board written as text and a fixed generator state. It calls the public `game/` API and compares the whole resulting board, score and events.

- **Slide geometry.** One asymmetric 5×5 board, swiped in all four directions, gives four expected boards. The same check runs on a 3×3 board. This catches row/column mix-ups, reversed lines and a hard-coded 4.
- **Line table.** Each row below is the only filled row of a 4×4 board (★ Joker, ■ stone). Each case also checks the score from its merges.

  | Row | Left | Right |
  |---|---|---|
  | `2 2 2 2` | `4 4 _ _` | `_ _ 4 4` |
  | `2 2 2 _` | `4 2 _ _` | `_ _ 2 4` |
  | `4 4 8 _` | `8 8 _ _` | `_ _ 8 8` |
  | `2 _ _ 2` | `4 _ _ _` | `_ _ _ 4` |
  | `★ 2 2 _` | `4 2 _ _` | `_ _ ★ 4` |
  | `2 ★ 2 _` | `4 2 _ _` | `_ _ 2 4` |
  | `_ 2 ■ 2` | `2 _ ■ 2` | ignored |
  | `2 2 ■ 2` | `4 _ ■ 2` | `_ 4 ■ 2` |

- **Ignored swipe.** The game comes back unchanged. No tile spawns, no stone or recharge ticks, and the generator and Undo snapshot are untouched.
- **Move order.**
  - A merge that makes 128 allows a stone in that same move's spawn.
  - A stone at countdown 1 crumbles before the spawn, so its cell counts toward room and can take the new tile.
  - A newly spawned stone shows 10 and doesn't tick on the move that spawned it.
- **Spawn odds table** (4×4, N = 4). This tests the odds that `game/` exposes.
  - Rows: boards with room 4, 6, 8, 12 and 16 give Joker/stone odds of 15%/0, 7.5%/0, 0/0, 0/7.5% and 0/15%.
  - Room counting inside those boards: a `2 2 2` run counts 2 merges, and so does a pair with empty cells between. A pair split by a stone doesn't count; a Joker–number pair does.
  - Caps: with a Joker already on the board, Joker odds are 0. With a stone already on the board, or a best tile of 64, stone odds are 0.
- **Powers.**
  - Smash refuses the last non-stone tile and can remove a stone. Swap refuses stones and needs two non-stone tiles.
  - Undo restores tiles (including stone countdowns), score and generator, so replaying the swipe gives the same new tile.
  - Undo doesn't take back the best tile, the win, or a refill earned on the undone move.
  - Undo is unavailable after a power has been used and after one undo.
  - A used power starts at the full recharge count. With 1 move left, the next move makes it ready. Ignored swipes and power use don't tick it.
  - A used bonus power returns to not drafted, not recharging.
  - Reaching the win tile leaves one refill waiting. Reaching the next doubling while one waits wastes the new one. A refill earned while every power is ready or bonus is wasted.
  - Picking a recharging power with a refill makes it ready; picking the not-drafted one makes it bonus.
- **Game end.**
  - Classic: a full board with one merge left isn't over; with none, it is.
  - Wild: a stuck board isn't over while there is a ready Smash, a bonus Swap with two non-stone tiles, or a waiting refill. It is over when the only ready power is Undo with nothing to undo.
  - A move that both wins and ends the game reports both.
- **Validation table.** Each row takes one valid Wild Blitz game, changes one thing, and expects it to be rejected. The unchanged game is accepted. Rows:
  - a tile out of bounds; two tiles in one cell
  - a duplicate id; an id ≥ nextTileId
  - a value of 3
  - style set to Classic while a Joker is on the board
  - two stones; a stone countdown of 0 or 11
  - bestTile below a tile
  - two not-drafted powers; movesLeft of 0, or above the recharge count
  - winSeen in Blitz
  - blitzMsLeft above 180,000

### 11.2 App flows (`app/`)

The whole app renders with the real game, save and stats code over jsdom's `localStorage`. Each flow starts from a crafted save, or none. It plays through keys, pointer drags and clicks, then checks what the player sees and what is saved. Only these are stubbed: the sound and vibration module, timers, `crypto.getRandomValues`, and page visibility.

1. **Resume exactly.**
   - First launch shows 4×4 Classic Endless with two tiles and no notice.
   - Arrow-key moves and a pointer drag work; a drag shorter than the minimum distance does nothing.
   - After a remount, the board, score and BEST are exactly the same.
   - Sound toggled off stays off after the remount and plays nothing.
2. **Corrupt save** (table).
   - Setup, sound, game and stats are each corrupted alone; game and stats through a broken invariant, not just a wrong type. Only that part resets, and the notice names it.
   - Unparseable JSON resets everything.
3. **Recorded exactly once.**
   - Start from a crafted game one move from game over, in a set whose 10th-best score equals the final score.
   - The move shows Game Over without "New best!". Stats shows played + 1 and leaves the new game out of the top 10, because ties keep the earlier game.
   - Remounting shows the finished game and records nothing. New Game then records nothing more.
   - The same ending in an empty set shows "New best!".
4. **New Game panel.**
   - It opens prefilled with the last setup, and arrow keys behind it don't move the board.
   - Esc and ✕ leave the current game untouched.
   - Start stays disabled until exactly two powers are picked.
   - Abandoning a game with points shows the points line and records the game. A game with 0 points shows no points line and records nothing.
   - The started setup shows in the setup label and becomes the next prefill.
5. **Powers on screen.**
   - Esc, or tapping the button again, cancels Smash targeting.
   - A swipe during targeting cancels it and plays the swipe.
   - Tapping a tile while targeting removes it and shows the recharge badge.
   - With a refill waiting, the glow and "Refill: tap a glowing power" show, and tapping a glowing power applies the refill.
6. **Blitz clock** (fake timers).
   - The clock stays at 3:00 until the first swipe.
   - It stops and shows PAUSED while Stats is open and while the page is hidden, and resumes on the next swipe.
   - A remount comes back paused at the same time.
   - The win banner doesn't stop it.
   - At 0:00 it shows Time's Up and records the game.
7. **Stats screen.**
   - From a crafted save, the grid shows each set's best score and best tile, with "—" for empty sets.
   - It opens on the current set.
   - Selecting a cell shows that set's played, wins · rate and Top 10, with ✓ on won games. An empty set shows "No games yet".

## 12. Out of scope for v1

- Undo in Classic; hints, solvers or AI.
- Accounts, sync, backup or export, sharing, leaderboards.
- Dark mode, themes, other palettes.
- Board sizes other than 3×3, 4×4, 5×5; Blitz durations other than 3 minutes.
- Daily boards, golden tiles, combo or streak scoring.
- Stats reset; full game history beyond the top 10.
- Keyboard shortcuts for powers; swipe-to-close on the New Game panel.
- Settings beyond the sound toggle.
